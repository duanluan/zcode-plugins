# ZCode Vision：图片视觉代理

[← 返回插件总览](../../README.md#-插件一览)

**装后必做：`/vision-setup`**——首次向导：确认识别端点（模型/key/是否走 headroom）并验证。默认配置开箱即用，向导主要用来确认与验证。

**原理**：给主模型发图片时（粘贴/拖拽），消息发给模型**之前**插件就先把图片交给视觉代理（默认两级链：跟随会话供应商 → GLM 直连兜底）识别，识别文字随消息带给主模型——主模型即使不支持图片输入（如 glm-5.3），也能像"看到"图片一样直接回答，不再自己去 OCR 或读图。

- **开箱即用**：默认链两级——`glm-session` 跟随**当前会话所用供应商**（走用户自己选的订阅额度，自定义供应商自动跟上），退回 GLM 订阅（Coding Plan）key 直连官方端点兜底；key 均可留空自动获取（ZCode Trust Build 赠送额度只从 ZCode 网关出、不放行无人值守调用，暂不进默认链，见 docs/adr/0002）
- **视觉小模型自动选**：跟随供应商时识别模型优先用内置映射表（Xiaomi MiMo → `mimo-v2.6-flash`、智谱系 → `glm-5.3-flash` 等），映射未命中才用代理自己的 model——glm-5.3-flash 遇上没有该模型的供应商不再报错刷屏
- **快速降级**：某代理连续失败 4 次（`skipAfterFailures` 可配）会暂时跳过 30 分钟（`skipMinutes` 可配）不再拖慢识别，期间任一次成功即恢复
- **按主模型触发**：主模型是 flash 小模型（`glm-5.3-flash` / `mimo-v2.6-flash` 等）时自动跳过不拦截——识别就是它自己；主模型能看图（如 `mimo-v2.6-pro`）时默认照常拦截、交给视觉代理识别注入（`forceIntercept` 选项，设 false 可关）
- **异常优先**：识别提示词要求先把界面截图里的错误、警告、异常状态逐字引用出来，再描述布局，关键报错不易被淹没
- **细节追问**：识别文字是一次性快照，识别文本附带图片完整路径，模型可随时调用 `vision_ask` 工具对原图定向追问（如"报错完整原文""右下角小字"），结果按图+问题缓存
- **过程中识图**：`vision_ask` 接受任意本地图片路径——AI 阅读文档、排查仓库遇到图片引用自己看不了图（Read 只得占位符）时，可随时调工具代看（总览或定向提问均可）
- **供应商可切换**：默认第一级代理 `glm-session` 跟随当前会话供应商；`/vision-proxy follow <代理名> <供应商>|off` 可改为固定跟随指定供应商或恢复直连配置；也可组多代理（`fallback` 依次尝试到成功、`pipeline` 逐级加工，`/vision-chain` 配置），每个代理可独立配供应商、模型、key、请求格式、单代理超时
- **不限图片数量与大小**；识别结果按「图片内容 + 链配置」缓存，同图同链不重复调用

### 🚀 使用

```
/vision-setup    # 装后必做：首次向导，确认识别端点并验证
/vision test     # 用最近一张图跑通识别链
/vision status   # 配置与缓存状态
/vision off      # 临时关闭（on 恢复）
```

配置文件 `~/.zcode/zcode-vision.json`。**图形化设置页面在 [zcode-pro](https://github.com/duanluan/zcode-pro) 中**：用「ZCode Pro」启动 ZCode 后，右键侧边栏底部的设置按钮（齿轮）打开设置窗口，「视觉代理」页可视化编辑代理链，与本文件是同一份配置。

已知边界：主模型能力按名字猜（任务索引只存 `<供应商>/<模型>` id，没有能力元数据）——认不出的新型号按纯文本处理照常识别；识别失败只把原因告诉主模型，绝不阻断消息。
