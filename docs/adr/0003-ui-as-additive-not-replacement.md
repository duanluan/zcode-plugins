# ADR-0003：UI 能力只做加法，工具文本输出保持不变

- 状态：已采纳（2026-10-14）
- 影响范围：四个插件的 MCP 工具与页面（rtk、headroom、zcode-vision、open-code-review）

## 背景

ZCode 3.15.1 起支持 UI Plugin：MCP 工具的结果可以带 `_meta.ui` 元数据，桌面端据此渲染交互页面。本仓库四个插件的工具结果有两类既有消费者：

1. **模型**：rtk 的压缩输出、headroom 的压缩标记、vision 的识别文字都是纯文本，模型靠读它们决定下一步动作；
2. **旧版客户端用户**（< 3.15.1，以及 Web/手机/远程工作区）：只展示文本结果，不渲染页面。

如果把工具结果改成“以页面为主、文本缩到最小”，旧客户端体验直接退化，模型侧的行为提示（AGENTS.md 里 rtk 的恢复指引、headroom 的取回指引）也要全部重写重调。

## 决策

所有工具的文本输出保持现状一字不动。页面能力只做加法：

- 工具定义/结果附加 `_meta.ui` 元数据与结构化副本（structuredContent），新客户端（≥ 3.15.1 桌面本地工作区）渲染页面，旧客户端忽略未知字段、继续读文本；
- 只给页面用的工具声明 `_meta.ui.visibility: ["app"]`，不进模型工具列表，避免污染模型的工具选择；
- 文本与结构化出现内容重复时，以文本为准，结构化只是页面视图的数据载体。

## 后果

- 旧客户端、新客户端、模型三方行为零回归；升级客户端即可获得页面，不升也不受影响。
- 个别工具要同时维护文本拼装与结构化组装两份代码，接受这点重复。
- 将来若官方收窄文本通道或页面成为主要消费方式，再评估是否切换为页面优先（另立 ADR）。
